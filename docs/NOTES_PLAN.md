# 笔记列表与笔记详情 — 安卓方案

**已确认（2026-10-26）**：按本方案先做 N1。**N1 状态：已完成**（未提交），验证见 §6。

依据（iOS 代码为准）：`NoteCreationView`（Today 方块进入的列表）、`NoteListViewModel`、`NoteCellView`
（`NoteHeaderBadgeView`、`NoteActionButtonsRow`、`NoteStatusIndicatorsView`、`VerseNoteGroupCell`、`PrayerVerseRevealButton`）、
`NoteDetailsView`（`LinkedVerseCard`、`NoteDetailActionsMenuButton`、`CommentInputSheet`、`TagPickerPopup`、`NotePinLogBuilder`），
以及 `NotesManager` 里对应的读写函数。

## 1. iOS 的结构

**列表**（Today 上任一方块 → `NoteCreationView(日期, 类型)`）
- 顶栏：左边类型菜单（全部、笔记、学习笔记、祷告、已应允、置顶、图片、经文、讲道、视频、加星），中间标题（滚动到的日期），右边标签菜单。
- 内容：按天分组（日期标题 + 右侧当前所选译本），每天内按 iOS 规则排序。
  筛选规则：当天创建或当天有评论的笔记；"置顶""已应允"不看日期；"全部"在今天时也列出所有置顶笔记；
  "经文"包含经文锚点和章级笔记；挂在锚点下的感想不单独成行。
- 每行（紧凑样式，点进详情）：类型标签（经文锚点显示"✝️ 约翰福音 3:16"，章级笔记显示"章 · 创世记 1"，
  祷告有经文时多一个 ✝️ 引用小标签，点开弹出经文）、状态图标（置顶、星级、标签、🙌）、正文
  （**经文锚点显示完整经文正文**，其他最多 4 行）、"N 条笔记 / N 条评论"、时间、"⋯"操作。
- 同一节的零散感想（没有锚点的，如网页端写的）合并成一组：经文一次，下面列笔记。
- 今天的列表底部有"＋"新建笔记（和 Today 的新建笔记同一个弹窗）。

**详情**（`NoteDetailsView`）
- 顶栏中间类型标签，右边"⋯"操作；底部"＋"加评论。
- 祷告带经文时上方先显示经文卡片；正文卡片（经文锚点为经文正文）；日期 + 状态图标。
- 经文锚点下列出当天的感想；其他笔记列出评论时间线（按月、按天，含置顶记录和"已应允"标记）。

**操作**（列表"⋯"和详情"⋯"共用）：已应允（仅祷告）、复制、置顶、删除（确认）、加评论、星级、标签、编辑（经文锚点和图片除外）。
经文锚点"加评论"实际是新建一条感想（不是评论）；祷告的加评论弹窗有"今天已应允"开关。

## 2. 安卓分两期

**N1（本次）**
- 列表页：类型菜单、标签菜单、按天分组、上面全部筛选/排序规则、三种行样式（普通、经文锚点、零散感想组）、
  祷告的 ✝️ 引用点开看经文、"＋"新建笔记。
- 详情页：经文卡片、正文卡片、日期与状态、感想列表、评论按天列出（先不画置顶记录的时间轴）。
- 笔记操作全部做：已应允、复制、置顶（含置顶记录 `PinLog`）、删除、星级、标签（选已有/新建）、编辑文字、
  加评论 / 加感想、"今天已应允"开关。写入格式与 iOS 一致，单元测试覆盖。
- 显示用的经文全部来自 `userVerses`（打开时缺的会补上，和 iOS 一样）；同步来的旧数据缺正文时退回显示 `content`。

**N2（之后）**
- 详情的完整时间轴（按月/日节点、置顶记录、已应允徽章，`NotePinLogBuilder`）。
- 评论自身的操作：编辑、删除、星级、标签。
- Today 的"回顾"页（`NotesReviewView` 左右翻页）。

## 3. 准备直接修正的 iOS 问题（写入格式不变，记入 IOS_ISSUES）

| 问题 | 影响 | 安卓做法 |
| --- | --- | --- |
| 编辑笔记（`updateNoteContent`）走的是已废弃的旧识别流程：改后的文字若以"John 3:16 …"开头，整条笔记被改成经文锚点，`content` 变成"·" | **用户文字丢失**；祷告也会被改成经文锚点 | 编辑只改文字，不改类型 |
| `linkedReflectionNotes` / `parentBibleVerseAnchor` 要求 `verseEnd` 完全相等（同 F3） | `verseEnd` 为空的数据感想挂不上锚点 | 空 `verseEnd` 视为等于 `verseStart` |

## 4. 暂不做 / 占位

- 图片笔记：安卓还没有图片同步，列表里显示"图片"占位和文字说明（OCR 文字照常显示）。
- 日期标题右侧的译本文字：iOS 点了进"译本设置"；安卓的译本设置页留到 Settings 标签页，这次只显示不跳转。
- 讲道/视频笔记页、章节详情页、记忆卡（"加入记忆卡"菜单）仍是"即将推出"。

## 5. 验收

单元测试（筛选/分组/排序规则、各操作的写入字段、感想挂接）；安卓模拟器上从 Today 各方块进入、操作后同步到
Firebase 本地模拟器，确认 `notes` / `noteComments` / `tags` / `PinLog` 文档与 iOS 格式一致。

## 6. N1 验证结果（2026-10-26）

- 单元测试共 220 个全部通过（本次新增 28：列表筛选/排序/分组 11、显示规则 8、笔记操作 9；对"取消置顶保留旧记录""隐藏感想"做了变异测试）。lint 无新问题。
- 安卓模拟器：从 Today 的"圣经""置顶""祷告"方块进入列表；经文锚点显示完整经文和"N 条笔记"；祷告的 ✝️ 引用弹出经文；
  详情页的经文卡片、感想、按天评论；"⋯"里置顶、星级、标签（新建）、编辑（祷告文字以"John 3:16"开头仍是祷告）、加评论/加感想、
  "今天已应允"。简体中文界面检查过。
- Firebase 本地模拟器：同步后 `notes`（`isPinned`、`starLevel`、`tagIds`、`isAnswered`、`answeredAt`）、`tags`、`PinLog`、
  `noteComments` 与 iOS 推送字段一致；用 CryptoKit 解密评论：已应允标记的正文就是配对评论的 id（与 iOS 相同）。
- 新发现的 iOS 问题见 `IOS_ISSUES.md` G1–G7。
- 未做（N2）：详情完整时间轴（月/日节点、置顶记录、已应允徽章）、评论自身的编辑/删除/星级/标签、回顾页；经文划线（`IndexedText`）叠层显示。

## 7. 按设计稿重做界面（2026-10-26）

依据 `docs/design/note-list/NOTE_LIST_DESIGN.md`（L1–L3）和 `docs/design/note-details/NOTE_DETAILS_DESIGN.md`（C1–C3）。
只改界面：筛选、排序、分组、`NoteAction` 和写入格式都没动。

**列表**：返回键 + 左对齐大标题（今天写"Today"，跟随滚动到的日期）+「Mon, Oct 26 · 6 notes」；横向滑动的类型胶囊；
标签按钮（选中后变成 `#标签` 胶囊）；分组标题「TODAY · MON, OCT 26」+ 译本；今天的「全部」顶部有 📌 PINNED 区（正文 2 行）；
三种卡片（普通 / 经文锚点 / 零散感想组）；祷告的经文胶囊点了在卡片里展开（上标节号）；底部居中「＋ New note」胶囊
（祷告筛选时是「New prayer」，打开新建祷告）；空列表的提示和次级按钮。
**详情**：自定义顶栏（类型胶囊 + 日期时间 + 「⋯」）；经文和笔记合成一张卡片，经文超过 3 节或 5 行时折叠、渐隐、
「Show all N verses」；卡片底部是标签、星标（轻点 0↔1、长按选级别）和「⋯」；评论（锚点叫 Reflections）按天分组、左边日期列；
底部输入栏（祷告未应允时上方有「🙌 Answered today」开关）。「⋯」改成底部菜单（C3），列表和详情共用。
**颜色**：只新增设计规定的 `scriptureInk`，另加「已应允」小字用的深绿 `answeredInk`（设计 §1.1 的 #1E6B33），两者都配了深色值。

**和设计稿的差异（安卓暂时做不了或不必做）**
- 经文区标题右边的「›」（跳到圣经阅读）没有放：安卓还没有圣经阅读页。
- 菜单里的「Change verse」没有放：还没有这个功能（设计说没有就先不显示）。
- 评论卡片右上角的「⋯」和长按操作栏（C4）、置顶记录行属于 N2，这次没做。
- 标签筛选只能选一个标签（现有逻辑），所以不会出现「2 tags」。
- 经文引用的范围用"1-6"（与 iOS 的 `BibleFormatter` 一致），设计稿写的是"1–6"。

模拟器上对照 L1/L2、C1–C3 逐项看过（含深色模式）；修了两个只在真机交互里出现的问题：菜单里的切换按钮要读最新的笔记状态
（第二次点「Pin」才不会又变回去），切换筛选或标签后列表回到顶部（否则置顶区被滚到上面看不见）。
