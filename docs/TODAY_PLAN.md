# 安卓 Today 页面移植方案

依据：iOS `TodayView` 及其组件（约 3,000 行 Swift，加上 `NotesManager` 中的相关逻辑）。
目标：**数据行为与 iOS 完全一致**（写入的字段、日期语义、`needsSync`），界面结构一致、用安卓原生组件实现。

**已确认（2026-10-26）**：
- 界面：结构照 iOS，安卓原生风格（Material 组件 + iOS 的 AppColor 配色）
- 先交付 **T1**
- §4 列出的 iOS 问题：安卓直接修正，写入格式不变；清单留给 iOS 以后修
- "已应允的祷告"：保持 iOS 现状（按祷告创建日统计）

## 1. iOS Today 页面组成（自上而下）

| 区块 | 内容 | 主要数据 |
| --- | --- | --- |
| **问候头部** | "Good morning/afternoon/evening"（按本地时间 5–11 / 12–16 / 其他）、日期、右侧头像 → 个人页 | 无 |
| **读经卡片轮播** | "Reading by Books"，可切换"按最近阅读 / 按书卷顺序"；每本书一张卡片：书名、已读/总章数、进度条、3 个章节按钮（今天读的=实心蓝，本轮读过=浅蓝，未读=灰）；空状态引导"标记你的进度" | `BookProgress`、`ChapterLog` |
| **快速添加** | 祷告 / 笔记 / 讲道 / 视频 四个按钮；右上"记忆卡 N" | 记忆卡活跃数 |
| **今日活动** | 高亮方块：置顶、加星、笔记、学习笔记、经文、祷告、已应允的祷告、图片（各带数量）；可展开卡片：今日读经章节、今日讲道、今日视频；"回顾"按钮 | 当天 `Note`（按 `createdAt` 或当天的评论）、`ChapterLog`、`Sermon`（`preachedOn`）、`YouTubeVideo` |
| **创建弹窗** | 新建祷告（标签 + 经文引用 + 正文）、新建笔记（经文引用 + 正文，自动识别正文里的经文）、新建讲道（手填或 YouTube 链接）、新建视频 | 写入 `Note`/`Tag`/`UserVerse`/`Sermon`/`YouTubeVideo`/`ChapterLog` |

点击后会跳转到的页面（安卓都还没有）：个人页、记忆卡、读经进度、章节详情、按类型的笔记列表、讲道笔记、视频笔记、每日回顾。
（2026-10-26：按类型的笔记列表和笔记详情已完成 N1，见 [NOTES_PLAN.md](NOTES_PLAN.md)。）

## 2. 安卓需要先补的基础（Today 依赖它们）

1. **配色**：把 iOS `AppColor` 整套浅色/深色色值和笔记类型标签色搬到安卓主题。
2. **圣经书卷数据**：66 卷的中英繁书名、缩写、章数（iOS `BibleBooks.swift`）。
3. **读经逻辑**：`BibleReadingManager` 的轮播数据和"标记/取消已读"（含同步后重复行的取舍规则）。
4. **经文引用解析**：`BibleReferenceValidation` / `parseFlexible` / `SermonReferenceParser`，配 iOS 行为的单元测试。
5. **经文正文**：内置 KJV（8.5 MB）、和合本（3.8 MB）。安卓在**构建时**转成预置数据库，首启无需解析；NIV/NKJV 需要 API.Bible 密钥（放 `dev.properties` / 正式密钥管理）。
6. **YouTube**：讲道用免密钥的 oEmbed；"保存为视频"要 YouTube Data API 密钥。

## 4. iOS 里发现的问题——安卓建议直接修正（并回报 iOS）

| 问题 | 影响 | 安卓做法 |
| --- | --- | --- |
| 新建讲道时对章节调用的是"切换已读"，今天已读的章节会被**取消** | 数据错误 | 只"标记已读"，不切换 |
| 自动识别的系列会覆盖用户手选的系列 | 用户选择丢失 | 用户选择优先 |
| 讲道重复提示设置后弹窗立即关闭，提示永远看不到 | 提示失效 | 正常显示 |
| `ChapterLog.readOn` 用"等于当天零点"判断今天 | 换时区时出错 | 按当天时间范围判断（写入格式不变，与 iOS 兼容） |
| 页面的"今天"在打开时固定，跨过午夜不更新 | 日期过期 | 回到前台/跨日时刷新 |
| 标签菜单用本地化文字"+ Tag"判断哨兵项 | 换语言出错 | 用独立的状态 |
| 章节按钮窗口缓存整个会话不清 | 显示不更新 | 不缓存 |

需要你确认的产品问题：**"已应允的祷告"** 现在按"祷告创建在当天"统计，而不是"应允在当天"（`answeredAt`）——是否应该按应允日期？

## 5. 不照搬的 iOS 实现细节

- Realm 的 `tick` / `.id()` 刷新技巧 → 安卓用 Room 的 Flow，自动刷新且不丢滚动位置。
- 页面间传递 Realm 对象 → 安卓只传 id。
- 中国版（无 YouTube）→ 以后用 Gradle 变体处理，T1 先不管。
